{% extends "pipeline/base.html" %} {% load static %} {% block title %}Review queue — figures waiting to be published{% endblock %} {% comment %} The page the review meeting is run from. The figure cropper used to publish straight to the website — one press, no second look — because a `PublicationImage` row *is* publication. It writes here instead now, and this is the only screen in the app that turns a crop into a public figure. So it is built the way the delete panel is built: say what is about to happen, in the words a person would use, with the number on the button being the number that was consented to. Two things it must never do, both learned elsewhere in this repo. It must not tell the reader to reload — a release redraws its own list. And it must not publish a set that has grown since the list was drawn: the count goes back with the press and the server refuses a mismatch (`services/review.py::release`). {% endcomment %} {% block content %}

Review queue

Figures waiting to be published

Everything the figure cropper makes waits here. Nothing on this page is on the public website, and nothing on it is visible to anyone outside the pipeline — except the supplier whose reagent it is, who can see their own figures through the data portal before release. Releasing is what publishes: the crop goes onto the gene's public page and OGA's recommendation is applied to the antibody at the same moment.

The recommended / not recommended button on each figure is OGA's verdict for that antibody in that application. It starts as whatever the cropper set and can be changed here up until release — which is the point of the meeting. Changing it alters nothing on the public site by itself.
