{% comment %} The chrome for every django-allauth page that is not one of the seven hand-written overrides in templates/account/. Without this file allauth serves its own layouts/base.html: Times New Roman on white, a bare "Menu:" list, no branding and no way back to the app. Change password, change email and account connections are all linked from the pipeline nav on every page, so that was the most visibly unfinished thing on the site — found by the twelfth field test, which reached it from the pipeline and could not get back without the browser's Back button. It is the *layout*, not three page overrides, because allauth builds every page from `{% templatetag openblock %} element {% templatetag closeblock %}` blocks over one of three layouts, all of which extend this file. So password change, email management, connections, email confirmation, reauthentication and anything allauth adds later are all covered at once — and none of allauth's own page templates is copied into this repo, where it would silently rot against the next version. The elements pick up Bootstrap in templates/allauth/elements/. Which chrome it wears depends on where the visitor came from. A person here may be an Academy user who has never seen the pipeline, so the site's own header is the default — but somebody who pressed "Change password" in the pipeline nav was getting Home, About Us, Publications, Roadmap, Partners and Contact over a page they reached from the sessions board: seven links out to the marketing site and none back to the work. `pipeline_chrome` (pipeline/context_processors.py) reads the `?next=` the pipeline nav already sends, and the top bar follows it. {% endcomment %} {% load static i18n %} {% block head_title %}{% endblock head_title %} – {% if pipeline_chrome %}YCharOS Pipeline{% else %}Only Good Antibodies{% endif %} {% block extra_head %}{% endblock extra_head %} {% if pipeline_chrome %} {% include "pipeline/_slim_nav.html" %} {% else %}
